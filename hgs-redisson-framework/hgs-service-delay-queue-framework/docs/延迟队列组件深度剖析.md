# 延迟队列组件深度剖析

---

## 一、组件总体架构

### 1.1 类清单（10 个）

```
com.hiddengemstore
├── config/
│   ├── DelayQueueAutoConfig              自动装配（注册 2 个 Bean）
│   └── DelayQueueProperties              配置属性（prefix = "delay.queue"）
├── api/
│   ├── producer/DelayQueueProducer       生产者入口
│   └── consumer/DelayQueueConsumer       消费者接口
└── internal/
    ├── base/DelayBaseQueue               公共基类（持有 RBlockingQueue）
    ├── producer/
    │   ├── DelayProduceQueue             单分区生产者（持有 RDelayedQueue）
    │   ├── DelayQueueProduceCombine      分片生产者组合（选择器 + N 个队列）
    │   └── IsolationRegionSelector       轮询分区选择器
    └── consumer/
        ├── DelayConsumerQueue            单分区消费者（双线程池）
        └── DelayQueueInitListener        启动时自动发现并初始化消费者
```

### 1.2 数据流全景

```
【生产端】
  业务代码
    → DelayQueueProducer.sendMessage(topic, content, delayTime, timeUnit)
      → computeIfAbsent 懒创建 DelayQueueProduceCombine
      → DelayQueueProduceCombine.offer()
        → IsolationRegionSelector.getIndex()           轮询选分区
        → DelayProduceQueue[index].offer()
          → RDelayedQueue.offer(content, delayTime)    写入 Redis

                    ── Redis 内部定时器，延迟到期后自动转移 ──

【消费端】
  RBlockingQueue（延迟到期的消息到达此处）
    → DelayConsumerQueue.listenStart()
      → listenStartThreadPool 单线程阻塞 take()
        → executeTaskThreadPool.execute()
          → DelayQueueConsumer.execute(content)        业务逻辑
```

## 二、功能设计与实现逻辑

### 2.1 生产端：消息分片 + 轮询路由

一个逻辑 topic（如 `order_cancel`）被拆为 N 个物理 Redis key：`order_cancel-0` ~ `order_cancel-(N-1)`。N 由 `delay.queue.isolationRegionCount` 控制，默认 5。

`sendMessage()` 执行流程：

1. `computeIfAbsent` 按 topic 懒创建 `DelayQueueProduceCombine`（线程安全，无锁读）
2. `DelayQueueProduceCombine` 内部通过 `IsolationRegionSelector` 轮询选出分区索引
3. 取出对应 `DelayProduceQueue`，调用 `RDelayedQueue.offer()` 写入 Redis

分片将单 key 压力分散到 N 个 key，消费端可并行消费 N 个分区，吞吐量成倍提升。

### 2.2 消费端：自动发现 + 分区对齐 + 双线程池

1. `DelayQueueInitListener` 监听 `ApplicationStartedEvent(项目启动完成事件)`
2. 从 Spring 容器获取所有 `DelayQueueConsumer` Bean
3. 对每个消费者按 `isolationRegionCount` 创建 N 个 `DelayConsumerQueue`，topic 命名为 `{consumer.topic()}-0` ~ `{consumer.topic()}-N-1`
4. 调用 `listenStart()` 启动每个队列的监听

双线程池职责分离：

| 线程池 | 配置 | 职责 |
|---|---|---|
| `listenStartThreadPool` | 固定 1 线程 | 阻塞在 `RBlockingQueue.take()`，持续监听 |
| `executeTaskThreadPool` | 可配（core/max/keepAlive/queue） | 异步执行 `DelayQueueConsumer.execute()` |

### 2.3 自动装配

`DelayQueueAutoConfig` 通过 `AutoConfiguration.imports` 自动加载，注册两个 Bean：

```java
@Bean DelayQueueInitListener delayQueueInitListener(RedissonClient, DelayQueueProperties)
@Bean DelayQueueProducer    delayQueueProducer(RedissonClient, DelayQueueProperties)
```

`DelayQueueProperties` 绑定 `delay.queue` 前缀，全部字段有默认值，零配置即可运行。

## 三、接口定义与参数说明

### 3.1 消费者接口

 `DelayQueueConsumer`（消费者接口）

```java
public interface DelayQueueConsumer {
    void execute(String content);  // 消费逻辑
    String topic();                // 该消费者监听的主题名
}
```

业务方实现此接口并注册为 Spring Bean，框架自动发现并启动消费。

### 3.2 生产者生成方法

`DelayQueueProducer.sendMessage()`

```java
public void sendMessage(String topic, String content, long delayTime, TimeUnit timeUnit)
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `topic` | `String` | 消息主题，需与消费者的 `topic()` 返回值一致 |
| `content` | `String` | 消息内容（业务方自行序列化/反序列化） |
| `delayTime` | `long` | 延迟时长 |
| `timeUnit` | `TimeUnit` | 延迟时长单位 |

### 3.3 配置属性类 

`DelayQueueProperties`

前缀：`delay.queue`

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `corePoolSize` | `Integer` | 4 | 消费线程池核心线程数 |
| `maximumPoolSize` | `Integer` | 4 | 消费线程池最大线程数 |
| `keepAliveTime` | `long` | 30 | 非核心线程空闲存活时间 |
| `unit` | `TimeUnit` | `SECONDS` | 存活时间单位 |
| `workQueueSize` | `Integer` | 256 | 消费线程池等待队列容量 |
| `isolationRegionCount` | `Integer` | 5 | 分区数（生产者和消费者必须一致） |

## 四、内部状态管理

### 4.1 生产端

| 所在类 | 字段 | 类型 | 作用 |
|---|---|---|---|
| `DelayQueueProducer` | `delayQueueProduceCombineMap` | `ConcurrentHashMap<String, DelayQueueProduceCombine>` | 按 topic 缓存分片处理器 |
| `DelayQueueProduceCombine` | `delayProduceQueueList` | `List<DelayProduceQueue>` | 按索引存储的生产者队列 |
| `DelayQueueProduceCombine` | `isolationRegionSelector` | `IsolationRegionSelector` | 分区轮询选择器 |
| `IsolationRegionSelector` | `count` | `AtomicInteger` | 当前轮询计数值 |
| `IsolationRegionSelector` | `thresholdValue` | `Integer` | 分区数阈值 |

### 4.2 消费端

| 所在类 | 字段 | 类型 | 作用 |
|---|---|---|---|
| `DelayConsumerQueue` | `runFlag` | `AtomicBoolean` | 防止 `listenStart()` 重复调用 |
| `DelayConsumerQueue` | `listenStartThreadPool` | `ThreadPoolExecutor` | 单线程，阻塞监听 |
| `DelayConsumerQueue` | `executeTaskThreadPool` | `ThreadPoolExecutor` | 可配线程池，异步消费 |
| `DelayConsumerQueue` | `delayQueueConsumer` | `DelayQueueConsumer` | 业务消费逻辑引用 |
| `DelayBaseQueue` | `redissonClient` | `RedissonClient` | Redisson 客户端 |
| `DelayBaseQueue` | `blockingQueue` | `RBlockingQueue<String>` | 阻塞队列，消息来源 |

### 4.3 `DelayBaseQueue` 设计意图

`RBlockingQueue` 被抽取到基类是因为生产者和消费者都需要它：

- 生产者通过 `blockingQueue` 获取 `RDelayedQueue`（`redissonClient.getDelayedQueue(blockingQueue)`）
- 消费者通过 `blockingQueue.take()` 阻塞消费

## 五、生命周期与事件处理

### 5.1 启动阶段

```
Spring 容器启动
  → DelayQueueAutoConfig 自动装配
    → 注册 DelayQueueProducer Bean
    → 注册 DelayQueueInitListener Bean

  → ApplicationStartedEvent 发布
    → DelayQueueInitListener.onApplicationEvent()
      → 从容器获取所有 DelayQueueConsumer Bean
      → 若为空 → return
      → 获取 isolationRegionCount
      → 遍历每个 consumer：
        → 创建 N 个 DelayConsumerQueue（构造时创建 RBlockingQueue + 两个线程池）
        → 调用 listenStart() 启动监听
```

### 5.2 运行阶段

- `listenStartThreadPool` 单线程持续阻塞在 `blockingQueue.take()`
- 消息到达 → 提交到 `executeTaskThreadPool` → 异步执行 `consumer.execute(content)`

### 5.3 停止阶段

- 监听线程收到 `InterruptedException` → 调用 `destroy()` 关闭 `executeTaskThreadPool`
- `listenStartThreadPool` 本身未被显式关闭
- `redissonClient` 生命周期由 Spring 容器管理

## 六、性能优化策略

| 策略 | 实现位置 | 说明 |
|---|---|---|
| 消息分片 | `DelayQueueProduceCombine` | 一个 topic 拆为 N 个 Redis key，降低单 key 压力 |
| 轮询路由 | `IsolationRegionSelector` | `synchronized` 保证均匀分布，阈值重置循环 |
| 异步消费 | `DelayConsumerQueue` | 监听线程只做 `take()`，业务逻辑提交到独立线程池 |
| 线程池可配 | `DelayQueueProperties` | 所有线程池参数通过配置调整，适应不同业务场景 |
| 懒初始化 | `DelayQueueProducer` | `computeIfAbsent` 按需创建分片处理器，未使用的 topic 不消耗资源 |
| 并发安全容器 | `DelayQueueProducer` | `ConcurrentHashMap` 无锁读，`computeIfAbsent` 保证原子写 |

## 七、设计模式

经严格对照 GoF 23 种设计模式，本组件使用了 **1 种**：

### 观察者模式（Observer）

`DelayQueueInitListener` 实现 Spring 的 `ApplicationListener<ApplicationStartedEvent>`，在应用启动完成后被自动回调。

| 角色 | 对应 |
|---|---|
| Subject（被观察者） | Spring `ApplicationContext`，发布 `ApplicationStartedEvent` |
| Observer（观察者） | `DelayQueueInitListener` |
| 触发方法 | `onApplicationEvent(ApplicationStartedEvent)` |

```java
@AllArgsConstructor
public class DelayQueueInitListener implements ApplicationListener<ApplicationStartedEvent> {
    @Override
    public void onApplicationEvent(@NonNull ApplicationStartedEvent event) {
        // 自动发现消费者并初始化队列
    }
}
```

通过 Spring 框架的事件机制间接实现，组件自身未手写 Subject/Observer 接口。
