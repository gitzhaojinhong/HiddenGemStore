## 二、功能设计与实现逻辑

### 2.1 核心能力

| 能力 | 说明 |
|------|------|
| 多实例支持 | 通过 YAML 配置动态注册多个布隆过滤器 Bean，每个业务（shop、voucher 等）独立实例 |
| 按名称获取 | 工厂模式，业务代码通过别名或 Bean 名称获取对应过滤器 |
| 前缀隔离 | Redis key 自动拼接应用前缀（`prefix.distinction.name`），多环境/多实例互不干扰 |
| 参数可配 | 每个过滤器独立配置预期插入数量（`expectedInsertions`）和误判率（`falseProbability`） |
| 自动装配 | Spring Boot AutoConfiguration，引入依赖即生效，零配置启动（无配置时无 Bean 注册） |

### 2.2 整体架构

```
                    ┌─────────────────────────────────────────────────┐
                    │              application.yml                    │
                    │  bloom-filter:                                  │
                    │    filters:                                     │
                    │      shop:                                      │
                    │        expected-insertions: 50000               │
                    │        false-probability: 0.01                  │
                    └──────────────────┬──────────────────────────────┘
                                       │
                    ┌──────────────────▼──────────────────────────────┐
                    │       BloomFilterHandlerRegistrar               │
                    │  (BeanDefinitionRegistryPostProcessor)          │
                    │                                                │
                    │  1. Binder 读取配置 → Map<别名, Filter>          │
                    │  2. 为每个 Filter 构建 RootBeanDefinition        │
                    │  3. 注册到 BeanDefinitionRegistry               │
                    └──────────────────┬──────────────────────────────┘
                                       │
                    ┌──────────────────▼──────────────────────────────┐
                    │            Spring 容器                          │
                    │                                                │
                    │  Bean: "shop"  → BloomFilterHandler             │
                    │  Bean: "voucher" → BloomFilterHandler           │
                    │  Bean: "redissonClient" → RedissonClient        │
                    └──────────────────┬──────────────────────────────┘
                                       │
                    ┌──────────────────▼──────────────────────────────┐
                    │       BloomFilterHandlerFactory                 │
                    │                                                │
                    │  get("shop") → BloomFilterHandler               │
                    │    .add(id) / .contains(id)                     │
                    └─────────────────────────────────────────────────┘
```

### 2.3 配置驱动的动态 Bean 注册

本模块的核心设计思想是：**不在代码中硬编码 Bean，而是根据 YAML 配置动态注册任意数量的布隆过滤器 Bean**。

这意味着：
- 新增业务过滤器只需在 `application.yml` 中添加配置，无需改代码
- 每个过滤器的容量和误判率独立可调
- 通过别名机制，业务代码可以用简短名称（如 `"shop"`）访问过滤器

## 三、自动装配模块 — config 包

### 3.1 BloomFilterAutoConfiguration

自动装配入口，通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册。

```java
@EnableConfigurationProperties(BloomFilterProperties.class)
public class BloomFilterAutoConfiguration {
    @Bean
    public BloomFilterHandlerFactory bloomFilterHandlerFactory() {
        return new BloomFilterHandlerFactory();
    }
    @Bean
    public BloomFilterHandlerRegistrar bloomFilterHandlerRegistrar(Environment environment) {
        return new BloomFilterHandlerRegistrar(environment);
    }
}
```

**职责：**

| 注册的 Bean | 类型 | 说明 |
|-------------|------|------|
| `bloomFilterHandlerFactory` | `BloomFilterHandlerFactory` | 工厂，用于按名称获取布隆过滤器 |
| `bloomFilterHandlerRegistrar` | `BloomFilterHandlerRegistrar` | 动态注册器，在 Bean 定义阶段注册多个过滤器 Bean |

`@EnableConfigurationProperties(BloomFilterProperties.class)` 的作用：

1. 将 `BloomFilterProperties` 注册为 Bean
2. 启用配置元数据生成（IDE 配置提示、自动补全）
3. 为将来可能的扩展保留注入能力

### 3.2 BloomFilterProperties

配置属性类，绑定前缀 `bloom-filter`。

```java
@Data
@ConfigurationProperties(prefix = BloomFilterProperties.PREFIX)
public class BloomFilterProperties {
    public static final String PREFIX = "bloom-filter";

    private Map<String, Filter> filters;

    @Data
    public static class Filter {
        private String name;
        private Long expectedInsertions = 20000L;
        private Double falseProbability = 0.01D;
    }
}
```

**配置结构：**

```yaml
bloom-filter:
  filters:
    shop:                          # ← 配置 key，作为别名 alias
      name: shop-id-bloom          # ← 可选，Bean 名称（省略则用 key 作为 Bean 名称）
      expected-insertions: 50000   # ← 预期插入元素数量，默认 20000
      false-probability: 0.01      # ← 误判率，默认 0.01（1%）
    voucher:                       # ← 别名
      name: voucher-id-bloom       # ← Bean 名称
      expected-insertions: 100000
      false-probability: 0.01
```

**`filters(Map)` 字段的冗余说明：**

> **注意：`filters` 字段在当前设计中是冗余的。**
>
> 因为 `BloomFilterHandlerRegistrar` 实现了 `BeanDefinitionRegistryPostProcessor`，运行在 Bean 定义阶段（此时 `@ConfigurationProperties` 注入还没完成），所以它使用 `Binder` 直接从 `Environment` 读取配置，不依赖此字段。YAML 配置结构不受影响，即使删除此字段，配置仍可正常读取。
>
> 保留此字段的原因：
> 1. 为将来可能的扩展保留可能性（如其他地方需要注入 `BloomFilterProperties`）
> 2. 保持配置类结构清晰，作为配置的"声明"
> 3. 生成 IDE 配置元数据（配置提示、自动补全）

### 3.3 BloomFilterHandlerRegistrar

核心组件，在 Bean 定义阶段动态注册多个 `BloomFilterHandler` Bean。

```java
public class BloomFilterHandlerRegistrar
        implements BeanDefinitionRegistryPostProcessor, PriorityOrdered {
    private final Environment environment;
    // ...
}
```

**为什么实现这两个接口？**

| 接口 | 说明 |
|------|------|
| `BeanDefinitionRegistryPostProcessor` | Spring Bean 生命周期扩展点，允许在 Bean 定义阶段（Bean 还没被实例化）修改或新增 Bean 定义。这里用它是因为需要根据配置动态注册多个 `BloomFilterHandler` Bean，而不是写死在代码里。 |
| `PriorityOrdered` | 控制多个 `BeanDefinitionRegistryPostProcessor` 的执行顺序。返回 `HIGHEST_PRECEDENCE` 表示最高优先级，确保在其他后处理器之前执行。 |

#### 3.3.1 `postProcessBeanDefinitionRegistry()` — 核心注册方法

```java
@Override
public void postProcessBeanDefinitionRegistry(BeanDefinitionRegistry registry) {
    Map<String, BloomFilterProperties.Filter> filters = resolveFiltersFromEnvironment();
    filters.forEach((alias, filter) -> {
        String beanName = StringUtils.hasText(filter.getName()) ? filter.getName() : alias;

        RootBeanDefinition bd = new RootBeanDefinition(BloomFilterHandler.class);
        bd.getConstructorArgumentValues().addIndexedArgumentValue(0,
                new RuntimeBeanReference("redissonClient"));
        bd.getConstructorArgumentValues().addIndexedArgumentValue(1, beanName);
        bd.getConstructorArgumentValues().addIndexedArgumentValue(2,
                filter.getExpectedInsertions());
        bd.getConstructorArgumentValues().addIndexedArgumentValue(3,
                filter.getFalseProbability());

        registry.registerBeanDefinition(beanName, bd);
        if (!beanName.equals(alias)) {
            registry.registerAlias(beanName, alias);
        }
    });
}
```

**关键概念解析：**

| 概念 | 说明 |
|------|------|
| `BeanDefinitionRegistry` | Bean 定义注册器，Spring 容器中负责管理 Bean 定义的核心接口。可通过它手动注册、移除、查询 Bean 定义。 |
| `RootBeanDefinition` | Bean 定义的具体实现类，包含创建一个 Bean 所需的全部信息：Bean 的类型、构造方法参数、作用域等。 |
| `RuntimeBeanReference` | 表示"运行时 Bean 引用"，告诉 Spring 在创建 Bean 时需要注入另一个已存在的 Bean（这里指注入名为 `"redissonClient"` 的 Bean）。 |
| `addIndexedArgumentValue(index, value)` | 按构造方法参数的索引位置设置参数值。index=0 表示第一个参数，以此类推。 |

**Bean 名称解析逻辑：**

```
如果 Filter.name 有值 → Bean 名称为 name，配置 key 注册为别名
如果 Filter.name 为空 → Bean 名称为配置 key（别名本身即 Bean 名称）

示例：
  配置 key="shop", name="shop-id-bloom"
    → Bean 名称: "shop-id-bloom"
    → 别名: "shop"
    → 两种方式都能获取: get("shop") 或 get("shop-id-bloom")

  配置 key="shop", name 未设置
    → Bean 名称: "shop"
    → 无额外别名
    → 只能通过 get("shop") 获取
```

#### 3.3.2 `resolveFiltersFromEnvironment()` — 配置读取

```java
private Map<String, BloomFilterProperties.Filter> resolveFiltersFromEnvironment() {
    Binder binder = Binder.get(environment);
    return binder
            .bind("bloom-filter.filters",
                    Bindable.mapOf(String.class, BloomFilterProperties.Filter.class))
            .orElse(Collections.emptyMap());
}
```

**Binder 是什么？**

`Binder` 是 Spring Boot 2.0 引入的类型安全配置绑定工具。作用是将配置文件（如 `application.yml`）中的属性值自动绑定到 Java 对象。

为什么不用 `@ConfigurationProperties` 注入？因为 `BloomFilterHandlerRegistrar` 通过 `BeanDefinitionRegistryPostProcessor` 在 Bean 定义阶段运行，此时 `@ConfigurationProperties` 注入还没完成，所以需要手动使用 `Binder` 读取配置。

#### 3.3.3 `getOrder()` — 优先级

```java
@Override
public int getOrder() {
    return Ordered.HIGHEST_PRECEDENCE;
}
```

`HIGHEST_PRECEDENCE`（值为 `Integer.MIN_VALUE`）表示最高优先级。确保布隆过滤器 Bean 在其他后处理器之前注册，这样后续处理器才能正常引用这些 Bean。

## 四、工厂模块 — factory 包

### 4.1 BloomFilterHandlerFactory

```java
public class BloomFilterHandlerFactory implements ApplicationContextAware {
    private ApplicationContext applicationContext;

    public BloomFilterHandler get(String name) {
        return applicationContext.getBean(name, BloomFilterHandler.class);
    }

    @Override
    public void setApplicationContext(ApplicationContext applicationContext) {
        this.applicationContext = applicationContext;
    }
}
```

**设计要点：**

- 实现 `ApplicationContextAware` 接口，是为了在普通类中获取 Spring 容器（`ApplicationContext`），从而手动获取 Bean。
- `get(name)` 方法的 `name` 参数支持两种形式：
  - 配置中的 key（别名），如 `"shop"`
  - Filter 的 name 属性（Bean 名称），如 `"shop-id-bloom"`

**使用示例：**

```java
@Resource
private BloomFilterHandlerFactory bloomFilterHandlerFactory;

// 通过别名获取
BloomFilterHandler shopFilter = bloomFilterHandlerFactory.get("shop");

// 通过 Bean 名称获取（等价）
BloomFilterHandler shopFilter2 = bloomFilterHandlerFactory.get("shop-id-bloom");
```

## 五、处理器模块 — handler 包

### 5.1 BloomFilterHandler

单个布隆过滤器处理器，封装了 Redisson 的 `RBloomFilter`。

```java
public class BloomFilterHandler {
    private final RBloomFilter<String> bloomFilter;

    public BloomFilterHandler(RedissonClient redissonClient,
                              String name,
                              Long expectedInsertions,
                              Double falseProbability) {
        RBloomFilter<String> bf = redissonClient.getBloomFilter(
                SpringUtil.getPrefixDistinctionName() + "-" + name);
        bf.tryInit(
                expectedInsertions == null ? 20000L : expectedInsertions,
                falseProbability == null ? 0.01D : falseProbability);
        this.bloomFilter = bf;
    }

    public boolean add(String value) { return bloomFilter.add(value); }
    public boolean contains(String value) { return bloomFilter.contains(value); }
}
```

**构造方法参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `redissonClient` | `RedissonClient` | Redisson 客户端，由 `hgs-redisson-common-framework` 提供 |
| `name` | `String` | 布隆过滤器名称，用于 Redis 中的 key 命名 |
| `expectedInsertions` | `Long` | 预期插入元素数量，为 `null` 时默认 `20000` |
| `falseProbability` | `Double` | 误判率，为 `null` 时默认 `0.01`（1%） |

**Redis key 命名规则：**

```
{prefix.distinction.name}-{filterName}

示例：
  prefix.distinction.name = "hgs"
  filterName = "shop-id-bloom"
  → Redis key: "hgs-shop-id-bloom"
```

`SpringUtil.getPrefixDistinctionName()` 从配置 `prefix.distinction.name` 中读取，未配置时默认为 `"hgs"`。这确保了不同部署实例的布隆过滤器在 Redis 中互不干扰。

**公开 API：**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `add(String value)` | 要添加的元素 | `boolean` | 向布隆过滤器中添加元素。返回 `true` 表示元素之前不存在（新添加），`false` 表示元素已存在。 |
| `contains(String value)` | 要检查的元素 | `boolean` | 判断元素是否**可能**存在。返回 `false` 表示元素**一定不存在**，返回 `true` 表示元素**可能存在**（有误判概率）。 |

## 七、内部状态管理

### BloomFilterHandler 的内部状态

| 字段 | 类型 | 生命周期 | 说明 |
|------|------|----------|------|
| `bloomFilter` | `RBloomFilter<String>` | 与 Bean 相同（应用级） | Redisson 分布式布隆过滤器实例，数据存储在 Redis 中 |

- `RBloomFilter` 是 Redisson 提供的分布式布隆过滤器，底层数据存储在 Redis 中
- `tryInit()` 方法是幂等的：如果布隆过滤器已存在且参数相同，不会重复初始化；如果参数不同，会抛出异常
- 布隆过滤器本身不支持删除元素，这是其数据结构的固有特性

### BloomFilterHandlerRegistrar 的内部状态

| 字段 | 类型 | 生命周期 | 说明 |
|------|------|----------|------|
| `environment` | `Environment` | 与 Bean 相同 | Spring 环境抽象，用于读取配置 |

### BloomFilterHandlerFactory 的内部状态

| 字段 | 类型 | 生命周期 | 说明 |
|------|------|----------|------|
| `applicationContext` | `ApplicationContext` | 与 Bean 相同 | Spring 容器引用，通过 `ApplicationContextAware` 回调注入 |

## 八、生命周期方法与执行顺序

### Spring Bean 生命周期中的执行位置

```
Spring Boot 启动
  │
  ├─ 1. SpringUtil.initialize()                     ← ApplicationContextInitializer（最早）
  │     保存 ApplicationContext 引用，后续 getPrefixDistinctionName() 依赖它
  │
  ├─ 2. AutoConfiguration.imports 发现本模块
  │     加载 BloomFilterAutoConfiguration
  │
  ├─ 3. @EnableConfigurationProperties
  │     注册 BloomFilterProperties Bean
  │
  ├─ 4. BloomFilterHandlerRegistrar 实例化
  │     Environment 注入到构造方法
  │
  ├─ 5. postProcessBeanDefinitionRegistry()  ← ★ 核心：Bean 定义阶段
  │     ├─ Binder 从 Environment 读取配置
  │     ├─ 为每个 Filter 构建 RootBeanDefinition
  │     ├─ 注册 BeanDefinition 到容器
  │     └─ 注册别名（如果 name 与 key 不同）
  │
  ├─ 6. postProcessBeanFactory()             ← Bean 工厂后处理（空实现）
  │
  ├─ 7. BloomFilterHandlerFactory 实例化
  │     ApplicationContextAware 回调注入容器
  │
  ├─ 8. RedissonClient Bean 创建             ← 由 hgs-redisson-common-framework 负责
  │
  ├─ 9. BloomFilterHandler Bean 创建         ← 此时才真正实例化
  │     ├─ 构造方法注入 redissonClient
  │     ├─ getBloomFilter(prefix + name)     ← 连接 Redis
  │     └─ tryInit(expectedInsertions, falseProbability)  ← 初始化布隆过滤器
  │
  └─ 10. 业务 Bean 创建和使用
       bloomFilterHandlerFactory.get("shop").contains(id)
```

**关键时序：**
- `BloomFilterHandlerRegistrar` 在步骤 5 执行，此时 Bean 还没被实例化
- `BloomFilterHandler` 在步骤 9 才真正创建，此时 `RedissonClient` 已经就绪
- 步骤 5 只是"告诉 Spring 要创建哪些 Bean"，步骤 9 才是"真正创建 Bean"
