# hgs-common 组件深度剖析

## 一、模块总览

### 1.1 模块定位

`hgs-common` 是整个项目的**最底层公共模块**，不依赖任何业务模块，为所有上层模块提供：

1. **Spring 基础设施** — 应用上下文工具、环境后处理器
2. **常量定义** — 全局配置键、分布式锁名、幂等业务名
3. **枚举定义** — 接口返回码、业务状态枚举
4. **异常体系** — 统一的异常层次结构
5. **线程本地变量** — 请求级参数传递
6. **日期工具** — 日期格式化、计算、区间操作

## 二、Spring 基础设施模块

### 2.1 SpringUtil — 应用上下文工具

**为什么实现 `ApplicationContextInitializer` 接口？**

`ApplicationContextInitializer` 是 Spring 提供的**容器初始化回调接口**，它的 `initialize()` 方法会在 `ApplicationContext` 被创建后、刷新（refresh）之前被调用。

**为什么不用 `@Component` + `@Autowired`？**

项目中很多地方需要**在非 Spring 管理的类中**（如工具类的静态方法、AOP 切面、锁名生成器）获取 Spring 容器的配置信息。普通的 `@Autowired` 注入只能用在 Spring Bean 中，而静态方法无法接收注入。

实现 `ApplicationContextInitializer` 的效果：
1. **Spring Boot 启动时自动调用** `initialize()` 方法（通过 `spring.factories` 注册）
2. **在所有 Bean 创建之前**就拿到 `ApplicationContext` 引用
3. 保存到 `static` 字段后，**任何地方都能通过静态方法访问容器**

```java
public class SpringUtil implements ApplicationContextInitializer<ConfigurableApplicationContext> {
    // 全局唯一的容器引用，启动时赋值，之后任何地方可访问
    private static ConfigurableApplicationContext configurableApplicationContext;

    // 任何类都可以直接调用，不需要注入
    public static String getPrefixDistinctionName() {
        return configurableApplicationContext.getEnvironment()
                .getProperty(PREFIX_DISTINCTION_NAME, DEFAULT_PREFIX_DISTINCTION_NAME);
    }

    @Override
    public void initialize(final ConfigurableApplicationContext applicationContext) {
        configurableApplicationContext = applicationContext;
    }
}
```

**在项目中的实际作用：**

```java
// AbstractLockInfoHandle.java 中生成分布式锁名称
// 这里是抽象类的普通方法，无法 @Autowired，只能通过静态工具类获取配置
public String getLockName(JoinPoint joinPoint, String lockName, String[] keys) {
    return SpringUtil.getPrefixDistinctionName() + "-" + getLockPrefixName() + ":" + lockName + ...;
    //     ↑ 静态调用，获取 "hgs" 前缀
}
```

### 2.2 SpringEnvironment — Bean 覆盖配置

**为什么实现 `EnvironmentPostProcessor` 接口？**

`EnvironmentPostProcessor` 是 Spring Boot 提供的**环境后处理器接口**，它的 `postProcessEnvironment()` 方法会在 Spring 环境（`Environment`）准备好之后、`ApplicationContext` 创建之前被调用。

**为什么不用 `@Configuration` 或 `application.yml`？**

`setAllowBeanDefinitionOverriding(true)` 这个设置需要在 **Bean 定义加载之前**就生效。如果放在 `@Configuration` 类中，Bean 已经开始注册了，来不及。`application.yml` 中也没有直接的配置项来控制这个行为。

实现 `EnvironmentPostProcessor` 的效果：
1. **在最早的时机**修改 `SpringApplication` 的配置
2. 确保后续所有模块的 Bean 注册都遵循"允许覆盖"的规则

```java
public class SpringEnvironment implements EnvironmentPostProcessor {
    @Override
    public void postProcessEnvironment(ConfigurableEnvironment environment, SpringApplication application) {
        // 在 Bean 定义加载之前，启用 Bean 覆盖
        application.setAllowBeanDefinitionOverriding(true);
    }
}
```

**在项目中的实际作用：**

本项目是多模块结构，不同模块可能通过 `@Bean` 注册同名的 Bean（例如多个模块都注册名为 `redissonClient` 的 Bean）。Spring Boot 2.x+ 默认**不允许** Bean 定义覆盖，会直接报错：

```
BeanDefinitionOverrideException: Invalid bean definition with name 'redissonClient'
```

启用 `allowBeanDefinitionOverriding = true` 后：
- 后注册的 Bean 定义会**覆盖**先注册的同名 Bean
- 多模块可以各自定义同名 Bean，最终以最后加载的为准
- 避免因模块间 Bean 名称冲突导致启动失败

**两个接口的执行时机对比：**

```
Spring Boot 启动
  ↓
Environment 准备完成
  ↓
SpringEnvironment.postProcessEnvironment()   ← EnvironmentPostProcessor
  → setAllowBeanDefinitionOverriding(true)
  ↓
ApplicationContext 创建
  ↓
SpringUtil.initialize()                       ← ApplicationContextInitializer
  → 保存容器引用到 static 字段
  ↓
Bean 定义加载 & 注册（此时 allowBeanDefinitionOverriding 已生效）
  ↓
Bean 初始化 & 依赖注入
```

### 2.3 spring.factories 注册

```properties
org.springframework.boot.env.EnvironmentPostProcessor=\
  com.hiddengemstore.environment.SpringEnvironment
org.springframework.context.ApplicationContextInitializer=\
  com.hiddengemstore.context.SpringUtil
```

通过 `spring.factories` 机制在 Spring Boot 启动最早期自动注册，无需 `@Component` 扫描。

### 4.3 枚举公共模式

所有枚举遵循统一的结构模板：

```java
public enum XxxEnum {
    // 枚举值定义
    VALUE_A(1, "描述A"),
    VALUE_B(2, "描述B");

    @Getter
    private final Integer code;
    private String msg = "";

    XxxEnum(Integer code, String msg) { ... }

    // 实例方法
    public String getMsg() { return this.msg == null ? "" : this.msg; }

    // 静态查找方法
    public static String getMsg(Integer code) { /* 遍历匹配 */ }
    public static XxxEnum getRc(Integer code) { /* 遍历匹配 */ }
}
```

每个枚举提供三个标准方法：
- `getMsg()` — 获取当前枚举的消息描述
- `getMsg(Integer code)` — 按 code 静态查找消息
- `getRc(Integer code)` — 按 code 静态查找枚举实例

## 五、异常体系模块 — exception 包

### 5.1 异常类继承结构

```
RuntimeException
  └── BaseException                     # 基础异常
        ├── HGSFrameException           # 业务异常（带 code + message）
        └── ArgumentException           # 参数异常（带 ArgumentError 列表）
```

### 5.2 BaseException — 基础异常

```java
public class BaseException extends RuntimeException {
    public BaseException() { }
    public BaseException(String message) { super(message); }
    public BaseException(Throwable cause) { super(cause); }
    public BaseException(String message, Throwable cause) { super(message, cause); }
    public BaseException(Integer code, String message, Throwable cause) { super(message, cause); }
}
```

所有业务异常的基类，继承 `RuntimeException`（非受检异常）。

### 5.3 HGSFrameException — 业务异常

```java
public class HGSFrameException extends BaseException {
    private Integer code;
    private String message;

    public HGSFrameException(BaseCode baseCode) {
        super(baseCode.getMsg());
        this.code = baseCode.getCode();
        this.message = baseCode.getMsg();
    }
    // ... 其他构造方法
}
```

支持两种构造方式：
- 通过 `BaseCode` 枚举构造（推荐）：自动填充 code 和 message
- 直接传入 code + message

### 5.4 ArgumentException — 参数异常

```java
public class ArgumentException extends BaseException {
    private List<ArgumentError> argumentErrorList;

    public ArgumentException(List<ArgumentError> argumentErrorList) { ... }
    public ArgumentException(String message) { ... }
    // ...
}
```

支持批量参数错误描述，适用于表单校验等场景。

### 5.5 ArgumentError — 参数错误详情

```java
@Data
public class ArgumentError {
    private String argumentName;  // 参数名
    private String message;       // 错误描述
}
```

## 六、线程本地变量模块 — threadlocal 包

### 6.1 BaseParameterHolder

基于 `ThreadLocal<Map<String, String>>` 的请求级参数传递工具。

```java
public class BaseParameterHolder {
    private static final ThreadLocal<Map<String, String>> THREAD_LOCAL_MAP = new ThreadLocal<>();

    public static void setParameter(String name, String value) { ... }
    public static String getParameter(String name) { ... }
    public static void removeParameter(String name) { ... }
    public static Map<String, String> getParameterMap() { ... }
    public static void setParameterMap(Map<String, String> map) { ... }
    public static void removeParameterMap() { ... }
}
```

**API 说明：**

| 方法 | 说明 |
|------|------|
| `setParameter(name, value)` | 设置单个参数 |
| `getParameter(name)` | 获取单个参数（不存在返回 `null`） |
| `removeParameter(name)` | 移除单个参数 |
| `getParameterMap()` | 获取参数 Map（不存在时创建 `HashMap(64)`） |
| `setParameterMap(map)` | 替换整个参数 Map |
| `removeParameterMap()` | 清除当前线程的所有参数（调用 `ThreadLocal.remove()`） |

**使用场景：** 在请求处理链路中传递上下文参数（如用户 ID、请求 ID），避免方法签名层层透传。

## 七、工具模块 — utils 包

### 7.1 DateUtils — 日期工具

提供日期格式化、解析、计算、区间操作等常用功能。基于 `java.util.Date` + `Calendar` + `SimpleDateFormat` 实现。

**核心能力分类：**

| 类别 | 方法 | 说明 |
|------|------|------|
| 获取当前时间 | `now()`, `nowStr()` | 获取北京时间（东八区） |
| 格式化 | `format()`, `formatDate()`, `formatDateTime()` | Date → String |
| 解析 | `parseDate()`, `parseDateTime()`, `parse()` | String → Date |
| 时间节点 | `getDateStart()`, `getDateEnd()` | 一天的 00:00:00 / 23:59:59 |
| 日期加减 | `addYear()`, `addDay()`, `addHour()` 等 | 基于 Calendar.add() |
| 星期操作 | `getWeek()`, `getWeekStr()`, `getWeekDate()` | 星期几、所在周日期 |
| 周/月区间 | `getWeekDateList()`, `getMonthDateList()` | 获取一周/一月的所有日期 |
| 日期差值 | `countBetweenSecond()` | 两个日期相差秒数 |
| 日期数字 | `getDateNo()`, `getDateTimeNo()` | 日期转数字（如 20220617） |
| UTC 格式 | `formatUtcTime()` | ISO 8601 格式化 |

## 八、生命周期与事件机制

本模块通过 `spring.factories` 在 Spring Boot 启动最早期自动注册，不依赖组件扫描。

**执行时机：**

```
Spring Boot 启动
  ↓
Environment 准备阶段
  → SpringEnvironment.postProcessEnvironment()   ← 允许 Bean 覆盖
  ↓
ApplicationContext 初始化阶段
  → SpringUtil.initialize()                       ← 保存容器引用
  ↓
后续 Bean 创建阶段
  → 各模块可调用 SpringUtil.getPrefixDistinctionName()
```

两个组件的执行顺序：`EnvironmentPostProcessor` 先于 `ApplicationContextInitializer`。

## 九、性能优化策略

| 优化点 | 位置 | 策略 |
|--------|------|------|
| ThreadLocal 初始容量 | `BaseParameterHolder` | `HashMap(64)` 避免频繁扩容 |
| 枚举静态查找 | 所有枚举 | `values()` 遍历匹配，枚举值少时性能可接受 |
